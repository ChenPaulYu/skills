# Dogfood — use the real workflow

## Workflow

Derive a short intent list from the user's requested outcome.
**Establish scope and conditions.** Use scratch data and an isolated browser/session.
Reuse existing authority for paid or external actions; ask only for missing consequential
scope. Review alone does not authorize source changes or an additional paid finale.

Operate the actual controls with representative inputs. Verify important outcomes
in the resulting state or actual output: an audio download needs decoded samples or
real playback, a saved change needs reopening. Capture friction points instead of
every routine action. Read `references/browser-check.md` for browser driving.

Reproduce apparent failures faithfully and inspect the real entry point before
attributing a cause. Distinguish missing product paths, invalid inputs, agent misuse,
demo quality and harness artifacts. Preserve the user's original work. Disclose known
problems promptly; independent-observation withholding needs explicit trial scope.

Report working flows, reproducible blockers, interventions and unrun checks against
the original intents. A useful demonstration does not establish an unused API is
necessary. Stop when the evidence answers the request; continue a confirmed fix only
under already-authorized implementation scope.

Save findings or captures only when requested or needed for a reusable reproduction,
using `references/saving.md`. Close only your own server/browser on every exit path.

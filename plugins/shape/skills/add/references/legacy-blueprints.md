# Read legacy work without migrating it

Use this reference only when the repository already keeps blueprints, a plan board,
TODO files, or a handoff. Read the actual shape rather than imposing a new schema.

- Find the existing entry point, linked tasks, decisions, implementation notes and
  artifacts. Read headings, status lines and next actions before deeper history.
- Resolve implementation claims against the mapped code repository and actual Git
  changes. Preserve reasons, unresolved questions and human acceptance separately
  from engineering completion.
- Treat the original work item as the progress owner. Update it in its established
  language and format when saving is authorized. A linked decision owns reusable
  rationale; do not duplicate the whole history into the task.
- Do not create thoughts, plans, boards or snapshots just because an older template
  describes them. A read-only status request creates nothing. A requested visual
  view can be disposable.
- Report ambiguous ownership or conflicting records. Consolidation, moves and removal
  belong to separately authorized cleanup with preserved reasons, repaired links and
  a verified recovery route. A normal read or session save does not migrate records.

Shape-view recovers work and shape-add saves it; shape-tend maintains records. Seek's methods can
clarify a choice or investigate a claim when requested. No legacy format requires a
chain of skills or grants implementation authority.

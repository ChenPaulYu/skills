# idea — keep the spark findable

Read `references/workspace-records.md` to locate the project's records and preserve
their ownership and lifecycle. This entrance is distinct from clarification: a spark
can be worth saving before anyone knows the questions it raises.

Before creating or updating project records or working artifacts, read
`references/workspace-records.md` to resolve the connected home and storage first. Read
`references/record-interface.md` for the shared frontmatter, honest dates, opening
conclusion and visible Relations. Keep existing records readable; do not invent parents.

Search existing project records for the same topic and reasons. Extend an existing
idea when it is the same thread; create a new one when it is independently useful.
Preserve the user's words or identify your summary as such. Record why it matters,
why it is deferred if stated, what would make it worth revisiting, and actual links
to related thoughts or evidence. Do not invent a reason the user did not give.

For a save request, write the record in the established destination under existing
authorization. A discussion alone need not create a file. Leave a captured idea
`saved` unless evidence supports another state; do not create a task, plan, deadline,
priority, or approval merely because the idea is now durable. Report its location
and one useful way to find it again (topic or related record).

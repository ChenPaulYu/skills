# Probe and source-roster follow-up — observed outcomes

> 2026-09-30 · ADR-135 · Three fresh gpt-6-luna contexts, four execution turns.

The generator discrepancy is covered by real-builder regression tests. Existing-evidence
probe selection and assessment worked in this sample. Whole-tree artifact retention still
failed after the first repair, and the simulated dogfood continuation was mixed. A second
retention-gate correction has offline verification only; it was not retried through a model.

## Method

The owner authorized the work and retained gpt-6-luna for dispatched execution. Planning,
criteria, source changes, artifact inspection, transcript review, and acceptance stayed
with the session. The grounded plan preregistered routing/assessment, artifact-tree
coverage/preservation, and tool-goal continuity. Three fresh contexts used separate Git
projects with a frozen full 24-skill pack and ordinary task prompts. Receipts, expected
edits, and rubrics stayed outside the packets. Exact skill-pack staging preserved the
artifact fixture's existing untracked note. Workers owned only their fixture workspaces.

The frozen pack was nav 0.20.3 / Shape 0.25.2, after the probe-protocol repair and before
the final shared retention-gate correction. The three results do not test that final gate.

Probe and artifact reused the previous natural prompts. Dogfood reused the CLI fixture
and received one simulated follow-up criticizing demonstration ordering, explicitly
remaining evaluation-only. This is a simulated continuation, not a human usability session.
No control arm, randomization, or metadata isolation was added. Host skills metadata and
standing instructions remained available. Actual body reads and tool calls were reviewed
in native logs; model metadata confirms gpt-6-luna for all four turns.

## Corrections and fixture limitation

The repeated retention miss justifies a sharper completion gate in the shared owner:
resolve coverage at the existing process-artifact root, inventory records and explicit
retained exceptions, then verify every excluded record or report the remaining exception.
This preserves existing files and does not enlarge index-cleanup authority. Final bundled
copies include this second correction; the trial pack preceded it. No fifth paid turn ran.

The new dogfood case inherited a report-only change allowlist, although separate request/
response captures are legitimate dogfood evidence. Preserve its original failed check.
The future case now admits those six capture paths. A separate copy of the result and
receipt was rechecked against that corrected scope; this is a checker re-evaluation,
not another model execution or a retroactive preregistered pass. Semantic review remains
mixed regardless of that correction. The catalog has 13 opt-in cases and starts no jobs.

## Source verification

`discoverSkillDirectories` reuses catalog discovery for catalog registration and both
builders' conversion/emission. Unit coverage rejects empty/resource-only directories and
non-file SKILL.md entries. Real-builder coverage generates both outputs before/after
residue, compares bytes, verifies active and historical namespace behavior, and confirms
that a real added skill still emits. Temporary fixtures leave source and Git index intact.

- Focused catalog/generator tests: 20/20 passed.
- Full offline suite: 128/128 passed, zero skipped.
- Owner manifests, Codex, and Cursor generated in order; normal marketplace, blueprints,
  and whitespace checks passed.
- Full compatibility audit in a temporary committed snapshot: 24/24 coverage, 11/11
  canaries, 15/15 negatives, browser contract OK, 2/2 preservation and 2/2 release smokes,
  frozen contract OK. The source index was untouched.
- Installed copies refreshed through the existing sync ritual and compared to their
  source projections; final versions are Shape 0.25.3, Codex adapter 1.0.12, Cursor
  adapter 1.0.4. Nav is 0.20.4 because its bundled retention references changed;
  the active 24-skill roster is unchanged.

Byte comparison caught ten stale Shape cache files after the second retention edit reused
the already installed intermediate 0.25.2 pin. Advancing the final pin to 0.25.3 and
running the existing sync ritual resolved them; no manual cache surgery was used.

The owner subsequently authorized committing and pushing these verified changes and
refreshing this machine's installed skills. That publication/update step adds no model
trials. Publication of the preceding ADR-134 change was completed separately.

## Usage and limits

Reported aggregate units: 1,109,075 input tokens, including 1,015,808 cached input tokens,
and 12,726 output tokens. Cached input is a subset; these are not monetary estimates.
Raw logs, receipts, and machine-specific fixture locations stay outside this public repo.

One sample per scenario cannot establish selection reliability, causal improvement, or
general agent quality. The CLI is a small synthetic stub. Paid-approval reuse and absent
preregistration were corrected in source; the trials launch no additional paid path, so
they cannot empirically establish that the approval gate works. Timely disclosure and
the second retention correction remain unverified in model behavior. No new skills,
automatic evaluation service, broad benchmark, or extra paid repetition were introduced.
